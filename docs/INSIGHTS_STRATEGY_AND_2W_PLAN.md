# Claude Insights Toolkit 정리 + 2주 액션 플랜

## 1) 프로젝트 의의 (Heading Summary)

Claude Insights Toolkit은 단순 대시보드가 아니라,
**Claude Code 사용 데이터를 `수집 → 진단 → 개선 → 이식(멀티 디바이스)`으로 닫힌 루프 운영**하는 서비스다.

핵심 목표:
1. 토큰/비용 최적화
2. Claude 활용 품질 개선 (더 좋은 프롬프트/운영 습관)
3. 작업 막힘(병목) 분석
4. 새 노트북에서도 빠른 복원/설정

---

## 2) 현재 강점

- 분석 커맨드 폭이 넓고 실사용 가능
  - `analyze`, `trend`, `patterns`, `power`, `sync`, `setup`, `daemon`
- 병목 분석 기반이 이미 존재
  - API 에러, 잘못된 접근, 세션 패턴, 마찰 유형
- 멀티 디바이스 sync 의도와 기반 구현 완료
- 리포트/스냅샷 기반의 시각화 파이프라인 동작

---

## 3) 핵심 개선 포인트

### P0 (필수)
1. 비용 KPI 모델 도입 (세션당 추정 토큰/비용)
2. 자동화 훅 트리거 일관화 (Submit/Session 종료 역할 분리)
3. 수집 헬스체크 (data/report/snapshot 생성 일관성)
4. sync 충돌 감지 및 사용자 안내 강화

### P1 (중요)
5. "이번 주 절감 임팩트 TOP3" 추천
6. 작업유형 × 마찰원인 매트릭스
7. 신규 노트북 온보딩 단축 (clone+setup+검증)

### P2 (확장)
8. 팀 단위 분석
9. 외부 연동/고급 추천

---

## 4) 2주 액션 플랜 (실행안)

## Week 1 — 신뢰도/자동화 고정 (P0)

### Day 1: 베이스라인 측정
- [ ] 현재 KPI 초기값 수집
  - 성공률, 병목 재발률, 최신 수집 시간, sync 실패 횟수
- [ ] 수집 파이프라인 점검 표 작성
  - `data`, `reports`, `snapshots` 각각 생성 조건 명시

**산출물**
- 베이스라인 문서 1개
- 파이프라인 점검 체크리스트 1개

### Day 2-3: 비용 KPI 스키마/계산 로직 추가
- [ ] 세션 단위 추정 토큰/비용 계산 로직 설계
- [ ] `power` 또는 신규 분석 경로에 비용 지표 노출
- [ ] "비용 상위 낭비 패턴" 출력 추가

**완료 기준**
- CLI에서 세션당 추정 비용 확인 가능
- 일/주 단위 비용 추세 출력 가능

### Day 4: 훅 자동화 일관화
- [ ] 자동 수집 트리거 정책 확정
  - Submit 이벤트: 경량 처리
  - Session 종료 이벤트: 본 수집 처리
- [ ] 중복 실행 방지(같은 날짜/세션에 대해 idempotent)

**완료 기준**
- 동일 이벤트 다중 트리거 시 중복 적재 없음
- 동작 정책 문서화 완료

### Day 5: 수집 헬스체크 + sync 안전장치
- [ ] 헬스체크 커맨드/출력 추가
  - 오늘 데이터 3종 생성 여부(data/report/snapshot)
  - 마지막 수집 시각, 누락 항목 표시
- [ ] sync 충돌 감지 시 가이드 메시지 추가

**완료 기준**
- 한 번의 명령으로 건강 상태 확인 가능
- sync 오류 시 사용자 복구 경로 즉시 안내

## Week 2 — 의사결정 강화/온보딩 개선 (P1)

### Day 6-7: 액션 추천 랭킹
- [ ] "이번 주 개선 액션 TOP3" 산출 로직
  - 기대 효과(성공률 개선/비용 절감) 기준 우선순위
- [ ] 추천 항목에 근거 지표 함께 출력

**완료 기준**
- 추천마다 근거 수치와 기대 효과가 함께 표시됨

### Day 8: 병목 매트릭스
- [ ] 작업유형 × 마찰원인 히트맵 데이터 생성
- [ ] 대시보드 또는 CLI 표 형태로 제공

**완료 기준**
- "어떤 작업에서 자주 막히는지" 즉시 파악 가능

### Day 9-10: 새 노트북 온보딩 플로우
- [ ] clone + setup + validate 절차를 하나의 가이드로 통합
- [ ] 필수 진단 항목 자동 점검
  - 경로/권한/hooks/sync 상태

**완료 기준**
- 신규 환경 세팅 시간이 크게 단축됨
- 설치 후 첫 분석까지의 단계가 명확함

---

## 5) 2주 KPI 목표

1. 수집 일관성: `data/report/snapshot` 동시 생성 성공률 95%+
2. sync 안정성: 충돌 미해결 건수 0
3. 비용 가시성: 주간 비용 추세 리포트 생성 가능
4. 개선 실행성: TOP3 액션 제안의 수락률 15%+
5. 병목 재발률: 주요 마찰 유형 재발률 20% 감소

---

## 6) 리스크 및 대응

- 리스크: 비용 데이터 원천 부족
  - 대응: 추정 모델(메시지 기반) + 신뢰구간 표시
- 리스크: 훅 이벤트 과다 실행
  - 대응: debounce/idempotency 키 도입
- 리스크: 다중 디바이스 충돌
  - 대응: 충돌 감지 + 표준 복구 가이드 + 사전 검사

---

## 7) Definition of Done (2주 종료 기준)

- [ ] 비용 KPI가 CLI/리포트에 노출된다
- [ ] 자동 수집 정책이 일관되고 중복 적재가 없다
- [ ] 헬스체크로 수집 누락을 즉시 찾을 수 있다
- [ ] sync 실패 시 복구 경로가 명확하다
- [ ] TOP3 개선 액션이 매주 자동 제시된다
- [ ] 병목 매트릭스로 작업 막힘 원인이 보인다
- [ ] 신규 노트북에서 빠른 재설정이 가능하다
